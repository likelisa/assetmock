# 游戏结局后的多世界分析

目标管家的未来可能性推演恢复为原互动游戏。买车、买房结束后，在结局与重玩之间自动生成 200 个模拟样本；自定义行动目标保持原游戏，不生成此分析。

## 计算口径

服务从归属当前会话与工作区的已结束 Run 读取冻结 setup。人物、余额、两条付款路径、贷款、费用、期限和事件规则不变，仅按固定种子重抽经历。每个样本的两方案共用随机序列，自动应对固定为 WAIT / DECLINE。玩家本局不混入统计，也不将玩家逐次选择复刻为样本策略。没有模型调用、额外压力参数或实时底账读取。

统计最低可用资金与出现资金缺口的样本数。失败月的负数代表缺口，不是实际账户余额；代表样本曲线在失败月停止。选取按两方案较低最低资金排序后的最低、中间、最高样本，选择过程可复现。

分布图共用金额边界与 0–100% 刻度，柱宽为区间实际计数 / 200。边界包含双方的零点、储备门槛与 1.25 倍门槛，颜色同时配文字。所有比例均为模型假设下的样本占比。

## 保存与接口

GET/POST `/api/simulations/runs/:id/worldline-analysis`。POST 要求 expectedVersion；当前工作区和 life-session 双重校验。新字段 SimulationReport.worldlineAnalysisJson 通过增量迁移添加。输入签名包含游戏 ID、版本、冻结 setup、计算版本、样本数量和应对规则；签名派生种子，重复请求用比较交换保留首份结果。原报告字段不变，导出整个 SimulationReport 时包含快照，工作区清除仍删除整条记录。

旧报告没有快照时按需生成；刷新读取同份结果。失败只影响分析卡片，保留原结局与重玩操作，可重试。重玩为新 Run，独立计算。

## 验收

自动化覆盖冻结条件、非默认贷款、200 个样本、30 年期限、早期失败、相同方案共享随机经历、分箱阈值与总数、重复请求与工作区隔离；浏览器覆盖买车、买房结局、手机显示、刷新恢复和失败重试。原独立游戏与自定义行动测试保留。

仍需两名未参与开发的使用者在无操作讲解的情况下验收：能区分本局和模拟样本，理解资金是否够用、样本应对规则和假设限制，并找到重玩入口。

# 目标管家统一买车资金规划

## 启用与范围

新界面由 `NEXT_PUBLIC_GOAL_FUNDING_ENABLED=1` 启用。默认关闭，完成下方两名独立用户验收后再为正式环境启用；修改该变量后需重新构建前端。关闭开关保留原目标界面及历史买车入口，不删除新方案。

首版覆盖买车目标确认、同预算同日期的全款及多份贷款报价、资金来源、四账户影响、确认采用和行动。未来可能性推演保持独立入口。资产管家“已创建目标”中的“开始规划”按钮已移除。

继承现有业务限制：一个工作区同时维护一个生效中的买车方案；其他目标资金仍参与保护与占用校验。买房、贷款申请、真实交易、自动转账和报告文件导出不在本次范围内。

## 实现位置与数据约定

| 层 | 文件 | 责任 |
| --- | --- | --- |
| 账户分类 | `src/domain/account-classification.ts` | 与财富概览复用四账户规则 |
| 确定性计算 | `src/domain/car-planning.ts` | 单份报价的最小必要本金、逐月还款、资金来源、约束及统一比较时间范围 |
| 报告 | `src/domain/goal-funding-report.ts` | 当前资产、筹备净变化、出资、付款后余额、规划内可用余额、资料依据和计算签名 |
| 会话与统筹 | `src/server/goal-funding.ts` | 目标关联、草稿确认、受控统筹、状态恢复和跨工作区检查 |
| 采纳 | `src/server/car-planning.ts` | 计算版本及签名复核、事务内写入方案/预留/行动、重复请求幂等 |
| 界面 | `src/components/goal-funding-*.tsx` | 对话与方案双栏、移动端切换、资料核对、方案比较与确认 |
| 接口 | `/api/goal-planning/[sessionId]` | GET 状态；POST `SAVE` / `GENERATE` / `ADOPT` |
| 历史报告 | `/api/car-decisions/[id]/report` | 工作区校验后的最新计算与历史生效版本 |

所有资金传输与报告字段使用人民币分的整数字符串，不从模型文本提取金额。新增报告版本为 `goal-funding-report-v1`，公式版本为 `unified-car-v1`。

复用 `CarDecision`、`CarEvaluationRecord`、`CarPlanVersion`、`CarFundingReservation` 和 `Action`；通用 `GoalDecision` 只作关联桥。此实现只增量扩展已有 JSON 数据，不新增表或修改列，因此没有新增 DDL 迁移。旧单份 `loan` 读取为一份报价；历史快照不自动重算。现有数据导出、清除和脱敏路径继续覆盖这些记录及 AgentRun 记录。

`ADOPT` 必须携带决策预期版本、计算记录 ID、候选标识及显式确认。服务再次校验工作区、资料签名和占用；采纳仅记录计划，不扣资产、不生成实际贷款或实际购车流水。实际购车继续从原核对入账入口处理。

## 计算与用户理解边界

- 未知保费、费用和可用日期保持未知；需要这些资料才能判断的方案阻断正式采用。
- 自有资金按本目标资产、预计结余及已确认奖金、流动资金、明确允许的投资来源顺序分配。费用、日期及 ID 保证同级排序稳定。
- 非现金来源需核对可用日期与动用费用；费用计入落地费用并检查总额。保险现金价值及受限资产不会自动解锁。
- 逐份录入贷款期限、名义利率、首付限制、本金上限、手续费、还款方式。修改报价字段后取消“已核对”状态，不将报价套用到另一期限。
- 未核实贷款仅为假设试算。报价额度、月供、储备底线及其他目标投入共同约束可行性。
- 四账户“付款后预计余额”包含未选、受限和已预留资产；“范围内可用”排除这些部分，但仍须保留整体应急底线。筹备净变化包含筹备期间的实际来源消耗，保证账户行可对账。
- 车辆估值未知时不输出完整净资产变化，不将全部车价描述为净资产损失。
- 右侧阶段与金额来自结构化服务结果。旧计算失效时明确标记为历史结果，计算失败不覆盖已采用报告。
- Agent 统筹使用有界的确定性资料核对，并记录 WEALTH → CASHFLOW / INSURANCE / INVESTMENT 的运行关系与证据；模型负责澄清和解释，不负责计算，也不会因此获得任意角色调用权限。

## 评委演示顺序（约 5 分钟）

1. 资产管家展示财富底账、收入支出及已有目标；已创建目标只有目标信息，无“开始规划”。
2. 进入目标管家，表达“一年后买车”，确认目标名称、预算和月份，指出此时只是创建目标，尚未采用方案。
3. 核对已有收支、保费、资金底线、可动用资产和报价；展示信息不足时的补齐提示。
4. 生成方案，在相同预算和日期下比较全款与不同贷款期限，说明自有资金、贷款本金、月供和融资成本。
5. 打开“账户影响”和资金来源，回答钱从哪里来、付款后还有多少、哪些资金保留给其他目标。
6. 说出“不动基金”或修改月供上限，确认调整草稿；展示原生效方案不被讨论内容覆盖。
7. 核对并采用，查看下一项行动；刷新页面证明目标、版本和行动恢复。说明采用不会自动划款。
8. 如需演示未来可能性，从独立入口进入；不将游戏报告当作正式采纳。

## 人工验收清单

下面全部使用虚构数据，不要求录入个人财务。金额单位为元，购车月份设为当前月后 12 个月，车价不含落地费用。

基础资料：现金 200,000；月收入 10,000；生活支出 5,000；无原贷款及其他目标；明确确认另行保费预留为 0；应急底线 60,000；落地费用 10,000；新增养车费每月 1,000；替代交通费 0。

| 案例 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 全款可行 | 车价 180,000 | 自有资金 190,000，预计结余出资 60,000、现金出资 130,000，付款后可用 70,000，购车后月结余 4,000 |
| 贷款可行 | 车价 200,000；分别录入 24/36/60 个月报价：年利率 4%、最低首付 20%、上限 160,000、手续费 100、等额本息 | 全款不足储备；各报价最小必要贷款本金为 10,100；月供和利息随期限变化，不能把一个期限当成所有期限的报价 |
| 未核实报价 | 取消“已逐项核对取得的报价” | 只可试算，不能采用贷款方案 |
| 全部不可行 | 在上述资金下把车价改为 1,000,000 | 无可行方案，显示原因和调整入口；原目标/生效方案不会被试算替换 |
| 资产保护 | 加入基金和保单现金价值；保留基金，不核实赎回费用 | 未允许基金不出资；未核实来源阻断正式采用；保单现金价值不可自动动用 |
| 版本与并发 | 采用后开两个会话；一个调整或修改底账，另一个尝试采用旧计算 | 旧计算不能覆盖新状态；重复确认不重复产生预留/任务 |
| 刷新与手机 | 刷新，切换“对话/方案”，打开账户及行动页 | 目标、版本、状态不丢失，页面无横向溢出；长表格可在自身区域滚动 |

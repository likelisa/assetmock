## 0. 结论先说

**能并，而且比示范里省力。** 示范做的是"从零造一个推演器 + 造一个界面"；本项目已经有四样东西，只差把它们接起来：

| 示范里要自己造的 | 本项目已有的 | 差距 |
| --- | --- | --- |
| 结算内核（逐月收支） | `src/domain/v2/engine.ts`（`reveal` / `settle`，确定性、整数分、账目自校验；`settlePath` 私有且固定 A/B） | 直接复用导出函数；只有第三条策略才需抽单路径纯函数 |
| 配对（同一世界线跑所有策略） | v2 的 A/B 两条 path **本来就共用一份 `tape: Draws[]`** | 已成立；本期就用这两条，第三条要另抽单路径函数 |
| 分档 / 口径纪律 | 规则文档 §3「安全垫 3 个月」、PRD「不预测」、示范 §7.4 教训 | 落成一个 `bandOf` |
| 承接结论的角色 | 五管家 agent 工具通道（`agent-tools.ts`，24 次工具预算、evidenceId 校验） | 加两个工具 + 一段 prompt |
| 报告与清除 | `SimulationOpening` / `SimulationReport` + `data-management.ts` 清除范围 | 加一张表并加进清除 |

所以规划的重点不是"搬 900 行 JS"，而是**五件事**：

1. 内核去重（一个规则真源，走 v2 的结算函数）；
2. 一个体积极小的 agent 工具契约；
3. 一个按文件 2 形式的引导式可视化；
4. **参数带出处**：真实数据为准，demo 先离线抓公开数据落成快照，运行时零网络，留好换真数据的接口（§6）；
5. **模块隔离**：崩了自己崩，不许外溢到别的页面（§7）。

**还有一条读代码才发现的结论**：项目里的「未来可能性推演 · 平行人生」本身就是"一条世界线 × 两个策略"的交互版（A/B 共用一份 `tape`）。它已经把 `reveal / settle / stateOf / initialState` 导出成纯函数，并且 `makeRun(..., { tape })` 支持注入随机记录。所以计算内核可以**零改动复用**；但要如实说明：场景③ 造新 run 需要一个正式的服务端 store 接缝，`PlanningHub` 也要加 tab 分支——"对既有行为零侵入"，不是"代码一行不改"（详见 §9）。

## 1. 模块边界（先说"不做什么"）

沿用规格 §2，并补上项目侧的边界：

| 做 | 不做 |
| --- | --- |
| 批量推演 N 条假设世界线，压成标量、分档、挑候选 | **不预测未来**；输出是"在 N 条里如何"，不是"将会如何" |
| 给 agent 一份**可读候选**，由 agent 选"最能说服用户的那条" | 不让 agent 决定事件、改数值、写账目 |
| 一个可把玩的可视化（翻卡、盲选、拖游标） | 不改写 `SimulationRun` 的既有局；不把世界线结果写回底账或目标 |
| 保存报告（可复现：种子 + 引擎版本 + 参数版本） | 不做"世界线导航/分支树编辑"，那是另一个产品 |
| 与「未来可能性推演」并列，共用底账、事件库、方案 | 不替代 v2 交互游戏（两者叙事定位不同，见 §9.1） |
| 参数的出处必须可追溯，缺依据就标"压力假设" | **不在运行时爬虫**（抓取离线化，见 §6.3）；不抓个人隐私数据 |

## 2. 架构：三层，一条数据流

```
底账 + 已选方案 + 目标            （已有：portfolio / planSet / goal）
        │
        ▼
① 冻结 opening（复用 server/simulations/opening.ts 的口径：来源、排除原因、金额分）
        │                         参数包 ← resolveParams()（快照 / 内置 / 预留接口，§6）
        ▼
② domain/worldline  ── 纯函数 ──►  { seed, 统计, 分档, 候选（≤8）, provenance }
        │                              │
        │                              ├──► ③ server/worldlines/tool.ts ──► agent 选卡 + 说服点
        │                              │
        └──► ④ components/worldline ──┴──► 用户把玩 + 保存报告
```

硬约束（照抄示范 §7 的血泪）：

- **判定、分档、颜色、排序、卡片标签必须由同一个标量 `minUsable` + 同一个 `bandOf` 推导**，不允许"卡片按排名分桶、分布按金额门槛"两套基准。
- **一个规则真源**：世界线内核走 v2 的结算函数，不另写一套账。否则同一底账在游戏页和世界线页给出不同数字，全部结论作废。
- **一个参数真源**：所有事件权重与金额只能来自 `WorldlineParams`，且每条都带出处（§6）。内核里不许出现魔法数字。
- **单位**：内核与接口一律**整数分**，展示层才 `/100`。示范用元，并入时一次性换算（示范 `cash 260,000` → `"26000000"`）。

## 3. 内核设计

### 3.1 复用 exported 纯函数，**本期不动 `engine.ts`**

`engine.ts` 已经导出了批量驱动需要的函数：`initialState / reveal / settle / stateOf / quietDraws`。现有玩法的策略恒为 A/B 两条，`settle` 一次结算两条 path，所以本期批量内核只跑 **A/B 两条策略**，不宣称支持 M 条或第三条策略：

```ts
const state0 = initialState(setup);
for (t = 0; t < months; t++) {
  const pending = reveal(state, tape[t], setup);
  const selections = policy(pending.decisions);
  const month = settle(state, pending, selections, setup);
  state = stateOf(month);
}
```

批量层对每条 path 单独维护 `active` 状态：某条 path 在 `settle` 返回 `failure` 后，记录 `firstShortfall` 与负的 `minBalanceMinor`，冻结该 path 的后续序列；另一条 path 仍可继续推进同一全局月份。这样与 v2 的实际行为一致：v2 不会让失败 path 继续产生收入或事件，但同一 `State` 仍可能为另一条 path 继续结算。只有未来支持第三条策略时，才另开 PR 抽取 `settleSinglePath` 并改造 path 容器。

### 3.2 一条世界线怎么跑

```
for i in 0..N-1:
  tape = [ draw(t) for t in 0..months-1 ]          // 种子 = seed + i*7919，增量稳定；与 v2 的 Draws 同构
  state = initialState(setup)                       // A/B 两条 path 从同一开局出发
  for t in 0..months-1:
    pending = reveal(state, tape[t], setup)         // 事件资格按各 path 当前状态判定（与游戏内一致）
    selections = policy(pending.decisions)          // 固定应对策略，两条 path 用同一策略
    month = settle(state, pending, selections, setup)
    state = stateOf(month); 记录 series[t]
```

- **配对成立**：`tape` 只依赖 `(seed, i)`，两条策略跑同一份 `tape`。差异只归因于策略。
- **改变 N 不改变前 N 条**：这是"再来一把"体验的地基，别破坏。
- **不用 `Math.random()`**，随机源写进 `engineVersion`。这里的 `engineVersion` 指**世界线内核版本**（新常量，如 `worldline-0.1.0`），与 v2 引擎无关，也不要和 `Rules.version`、`rulesVersion` 混用。`Draws` 的取值域与 `tapeFor()` 完全一致（5 个整数，`0 ≤ n < 1000000`），所以世界线的 tape 能直接喂给游戏（§9.4 场景 ③）。

### 3.3 每条世界线必须产出的字段（照规格 §6）

| 字段 | 定义 | 用途 |
| --- | --- | --- |
| `premise` | 一句话可复述：哪月发生什么 | 卡片正面、agent 说服点 |
| `minBalanceMinor` | 逐月可用资金（现金+投资）的最低点；若某条 path 失败，按该月 `failure.shortfall` 构造负值 `-shortfall`，不读取失败后冻结的 `Balance` 作为缺口 | **唯一判定标量** |
| `firstShortfall` | 首次不足的月份 + `failure.shortfall` 金额 | 卡片、报告 |
| `status` | 每条策略 path 的 `completed` / `failed`，不是整批 Run 的单一状态 | 分档的分母口径 |
| `cause` | `{shock, trigger}`，能区分"冲击型事件"与"仅开销波动" | 悲观档优先选因果两段式 |
| `fragilityMinor` | P90 − P5 | 波动幅度 |

### 3.4 需要拍板：失败后算满，还是失败即停

示范坚持"算满 12 个月"（否则分布口径不同）。但 v2 的规则是 `UNFUNDED_GAP` 即终局、不允许负现金继续（规则文档 §3）。两种口径：

- **口径 A（算满）**：失败后继续记负值。分布对比更平滑，但等于允许"不存在的透支"。
- **口径 B（推荐，逐 path 失败即停并记负值）**：失败月记 `minBalance = -failure.shortfall`，该 path 后续不再推进；另一条策略 path 仍沿同一 tape 继续到期。所有 path 仍有同一个标量定义，可比性保留，也不与 v2 规则冲突。

推荐 B，并把「中途失败条数」与「到期不足条数」**分开展示**（示范踩过的坑，见开发说明 §6.2 注）。

### 3.5 分档门槛

```ts
floorMinor(strategy) = (必需支出 + 到期月供) × 3     // 与 v2 的 BALANCED 安全垫同源
bandOf(v) = v < 0 ? 'bad' : v < floorMinor(s) ? 'tight' : 'ok'
```

⚠️ 两个策略的 `floorMinor` 不同（月供不同），所以两栏色带高度本来就不同——这是正确的，不是 bug；若要水平对齐必须同时改卡片判定（开发说明 §9.7 的教训）。

### 3.6 选取：③ 统计 与 ④ Agent 分开（规格 §5）

- **③ 保留**（可复现、纯函数）：按 `worstBand` 分到 bad/tight/ok → 展开槽位（偏乐观/乐观）→ 每槽取**中位附近、事件数少、signature 互斥**的若干候选（每槽 2–3 条，共 ≤ 8）。
- **④ 换掉**（示范里明确标注是占位）：把候选交给 agent，由它在候选里挑"最能说服这个用户的那条"，并写说服点。**③ 是闸门**，所以 agent 挑不出"天天被雷劈"的线。

### 3.7 "开销补刀"怎么做：本期不用改引擎

示范的悲观档靠"大事件压薄余量 + 某月开销偏高补最后一刀"，而 v2 没有月度开销噪声。若为此在 `settle` 里加 `livingSpike` 事件，就**必须动 `engine.ts`**，与 §9 的零侵入原则冲突。所以分两步：

**本期（零侵入）**：把"生活开销"做成**每条世界线的底色档**而不是月度噪声。

```ts
// 只改纯数据，不动引擎：同一条线的两个策略共用这份 setup
const drift = pick(tapeSeedOf(i), [0, 0.05, 0.12]);      // 0 / +5% / +12% 三档
const setup = { ...opening.setup, profile: { ...profile, living: roundCents(profile.living * (1 + drift)) } };
```

- 分档门槛 `floorMinor` 也随之用该线的 `living` 计算（同一个真源）；
- 卡片前提里写明"生活开销按 +5% 档"，不藏假设；
- 代价：不再有"某一个月补最后一刀"的月度因果，悲观叙事略弱，但**换来零侵入**。

**后续（允许动引擎时，单独 PR）**：`EventKind` 加 `'livingSpike'`（500 元一档），`settlePath` 里 `living += spike`；因为 v2 的 `reveal` 永不产出它，交互游戏数值一字不变，回归测试天然通过。**版本要分开记**：世界线自己的 `worldlineRulesVersion`（如 `wl-r1`）写在报告里；v2 的 `Rules.version` 目前只允许 `'0.2.0' | '0.3.0'`，想升 `0.4.0` 必须同时改类型、规则文档与既有验收记录，属于独立 PR，不能顺手写。届时才需要 §9.3 提到的那次行为不变重构。

### 3.8 事件卡：频率归概率，强度归卡片

§3.7 的"底色档"只是一档。把它一般化就是**事件卡**：

> **一张卡 = 一个冲击的强度档 + 一句可复述的前提 + 它引用的真实数据。**
> 频率仍由 `rules.probabilities` 决定，强度由卡片分档写进该条世界线的 `setup`。

为什么不新增事件种类：v2 只有 5 类事件，金额/时长/跌幅都是 `rules` 里的纯数据；要加种类就得改
`engine.ts`。所以卡片只做两件事——**选档**（每条线抽一档）与**注明出处**，一个字都不改引擎。

**谁在选档：agent。** 引擎不替用户决定"要不要考虑养育成本"，也不替 agent 决定"这位用户该不该按大病高档跑"。
agent 先看卡目录（`getEventCards`），再提交卡组（`proposeEventCardPlan`：哪张参与、哪张排除、哪一档钉死，
每条都带 `rationale` 与 `evidenceIds`），引擎只负责校验卡组的结构底线，然后在卡组上跑。
权限边界见 §4.1.1。

四组强度梯度（参与抽样）+ 叙事卡（不抽样）：

| 梯度 | 门类 | 卡片（权重） | 落到 setup |
| --- | --- | --- | --- |
| `living.level` | B/I | 开销如常 0（6）· +5%（3）· +12%（1） | `profile.living` |
| `medical.severity` | C | 5 万（5）· **10 万（3）** · 20 万（2） | `rules.medicalCost` |
| `market.severity` | D | 15%（2）· **20%（4）** · 30%（3）· 45%（1） | `rules.marketDropRate` |
| `rate.env`（仅住房） | E | **3.50% LPR（7）** · 4.20% LPR（3） | `plans[].offer.annualRate` + 重算月供 |
| 叙事卡 | A/F/G/H | 恢复期 3/6 月 · 退休与缴费年限 · 养育成本 · 失业金期限 | 只进报告与 agent 论据 |

三条硬规矩（已实现成测试）：

1. **数值不许手写**：`effect` 必须等于它引用的参数值 —— 改一处忘另一处，测试先红；
2. **出处口径**：第三方/智库（精算师协会、育娲人口）必须在 `label` 点名机构；压力假设不许写"研究显示"；
3. **前提只在相关事件真的发生时提档位**：抽到"大病高档"但这条线没生病，卡片上不写那句。

`rate.env` 是这一层意外赚到的：同一份底账放在 3.50% 与 4.20% 两个 LPR 环境下，月供会不同——
这正是世界线要展示的"环境差异"，而且完全靠纯数据实现（重算 `payment` 即可）。

## 4. Agent 工具契约

### 4.1 四个工具

`src/server/worldlines/tool.ts`，注册进 `agentTools`：

| 工具 | 角色 | kind | 说明 |
| --- | --- | --- | --- |
| `getEventCards` | GOAL / WEALTH / CASHFLOW | QUERY | 读卡目录（按目标过滤）：每张卡的强度档、前提、依据等级、默认权重；≤6KB |
| `proposeEventCardPlan` | 同上 | PROPOSE | 提交 agent 选定的**卡组**（哪些卡参与/排除/钉档 + 理由 + 依据）；服务端校验后才会被采纳 |
| `simulateWorldlines` | 同上 | COMPUTE | 按卡组批量推演 → 统计 + 分级候选（≤8 条），体积 ≤ 6KB |
| `getWorldlineDetail` | 同上 | QUERY | 按 `(id, strategy)` 重算某条线的月份明细（抽样 ≤12 月），说明"第几个月开始不够" |

**顺序是强制的**：先看目录 → 再提交卡组 → 再跑。没有卡组也能跑（回落到默认全卡组），
但那就等于"agent 没做判断"，报告里会写 `cardPlanId: plan.default`。

### 4.1.1 卡片的权限归谁（这条最容易做错）

| 谁 | 有什么权 | 明确没有的权 |
| --- | --- | --- |
| **引擎** | 结算顺序、事件发生（频率阈值）、结构底线 | 不替 agent 选卡，也不"随机替用户决定要不要考虑养育成本" |
| **agent** | 根据已知信息选卡：哪张参与、哪张排除、哪一档钉死、档位相对权重；并为每条判断写理由与依据 | **不能改数字**（金额/幅度/利率/频率锁在参数包）、不能编卡、不能静默砍尾部 |
| **用户** | 确认或改写卡组（PROPOSE → 确认）；看到的报告里带"这次排除了什么" | — |

卡组结构：

```ts
type CardPlan = {
  id: string; version: string; target?: string;
  entries: Array<{
    cardId: string; ladder: string;
    mode: 'sampled' | 'fixed' | 'excluded';
    weightOverride?: number;     // 仅 sampled，1..原权重×3
    rationale: string;           // 一句话判断
    evidenceIds: string[];       // 引用用户事实 / 上一轮工具结果
  }>;
  notes: string[];               // 排除整组梯度、或砍掉最重档时必须写
};
```

三条结构底线（已实现成测试，agent 绕不过）：

1. **不能改数字**：卡组里根本没有金额字段，只有 `cardId` 与 `mode`；
2. **不能静默砍尾部**：把某梯度最重档排除，`notes` 里必须点到它；整组排除必须点到梯度名；
3. **不能无理由**：每条 `rationale` 必填；叙事卡也必须在排除时说明理由。

复现：结果的 `cardPlanId + cardPlanHash + seed + paramsVersion` 四个一起存，才复述得出"我们假设了什么"。


### 4.4 三处接线（都在既有代码里加，不加新机制）

1. `agent-tools.ts`：两个 `tool(...)` 条目 + schema。
2. `five-agent-runtime.ts` 的 `complete()`：`validEvidence` 里放行 `WORLDLINE:` 前缀（照 `PAPER_` 的写法，一行）。
3. `domain/agents.ts` 的目标管家 prompt：新增一段"世界线怎么用"——只允许引用过筛候选、只写"如果…则…"、禁止概率与最坏值、必须给出 `seed / n / paramsVersion`，并按 `basis` 决定措辞（§6.5）。

### 4.5 确定性、缓存、失效

- `cacheKey = sha256(openingSignature | strategyKeys | months | n | seed | paramsVersion | responsePolicy | engineVersion | worldlineRulesVersion)`；进程内 LRU（如 32 条），不落库。
- 底账 `portfolioRevision` 或已选方案变化 → 返回 `STALE`，不静默复用（照 `SimulationReport.stale` 的既有做法）。
- 同一入参重复调用结果**逐字节一致**（含 `seed` 与 `paramsSha256`）。

## 5. 接口与存储

`/api/worldlines/[...route]`，与管理器路由同构（`endpoint(...)` + `X-Workspace-Id`）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `opening?goalId=` | 冻结输入草稿：来源资产、纳入金额、排除原因、默认策略 |
| GET | `params` | 当前参数包 + `provenance` + `dataStatus`（页面显示"这些假设从哪来"） |
| POST | `runs` | 跑一批：`{openingId, n, k, seed, paramsVersion, responsePolicy, focus}` → `{runKey, seed, paramsVersion, bands, quantiles, candidates, minUsables[], 每月分位带}` |
| GET | `runs/[runKey]` | 同上（纯函数重算，不查缓存，保证永远一致） |
| GET | `runs/[runKey]/lines?ids=W-037,W-021` | 被选线的逐月明细（≤6 条） |
| GET | `reports` / POST `reports` | 列表 / 保存报告（用户点击才写） |

**传输契约（性能关键）**：
- 每月分位带：`months × strategies × {p5,p50,p90}` → 60 月 × 2 × 3 ≈ 360 个数字。
- 右侧边际分布：**只下发每条的 `minUsable` 一个数**（200 条 = 200 个数字），直方图在客户端算；顺带画出"细线雾"的 rug。
- 代表线（≤6 条）：完整 `series`。
→ 一次"把玩"首屏 JSON 约 30–60KB，而不是几 MB。

**存储**：新增一张表，够用而不重：

```prisma
model WorldlineReport {
  id, workspaceId, goalId?, sessionId?, runKey,
  openingSignature, sourceRevision, seed,
  paramsVersion, paramsSha256, paramsJson,       // 参数包快照：出处随报告一起冻结（含 facts/assumptions/sourceQuality）
  engineVersion, worldlineRulesVersion, v2RulesVersion,  // 世界线自己的版本 + 复现用的 v2 规则版本
  resultJson, createdAt, staleAt?, savedAt?
}
```

- 用户不点"保存"就不落库（世界线本身是纯函数，随时重算）。
- **必须显式加进清除链路**（不能指望"自然覆盖"）：`purgeDatabase()` 里与 `simulationOpening` / `simulationReport` 并列 `worldlineReport.deleteMany`；`dataOverview()` 返回值加 `worldlineReports`；`deletionPreview()` 的 affected 文案写明"世界线报告"；并补一条删除测试（删除工作区业务资料后该表为空）。
- 迁移走既有流程：`prisma migrate` + `npm run setup`，不做 `db push`。

### 6.1 契约：一个参数包

```ts
export type ParamSource =
  | { kind: 'BUILTIN' }                          // 内置压力假设（冻结、带版本）
  | { kind: 'SNAPSHOT'; documentId: string; url: string; retrievedAt: string; documentVersion: string; quote: string; fallbackUrl?: string }
  | { kind: 'USER'; confirmedAt: string };        // 用户确认过的自定义假设

export type Param = {
  key: string;                                    // 如 'jobLoss.prob.monthly'
  value: number;
  unit: 'RATIO' | 'CNY_MINOR' | 'MONTHS' | 'DIMENSIONLESS';
  source: ParamSource;
  basis: 'PUBLIC_STATISTIC' | 'DERIVED' | 'PRESS_HYPOTHESIS'; // 三档，见 6.1 下方
  sourceQuality?: 'OFFICIAL' | 'THIRD_PARTY' | 'THINK_TANK';  // PUBLIC_STATISTIC 时必填
  label: string;                                  // 人话，页面与 agent 直接引用
  derivation?: { formula: string; inputs: string[] }; // 仅 DERIVED
};

export type WorldlineParams = { version: string; sha256: string; facts: Param[]; assumptions: Param[] };
```

- **没有 `WEB` 分支**：本期运行时零网络，P5 的"刷新参数"属于显式的离线重建/快照更新，不引入第三种运行时来源；少一个分支就少一类复现漏洞。
- `sourceQuality` 解决"第三方/智库算不算公开统计"：仍可 `PUBLIC_STATISTIC`，但只有 `OFFICIAL` 允许写"国家统计局数据"，`THIRD_PARTY` / `THINK_TANK` 必须在 `label` 里带机构名；测试断言 `OFFICIAL` 的 url 域名在白名单内。
- `fallbackUrl` 用于原文与官方转载并存的情况（调研稿附录 B），两处 `quote` 必须一致。
- **复现键**从 `(seed, n, k)` 升级为 `(seed, paramsVersion, engineVersion, worldlineRulesVersion, v2RulesVersion)`；报告全部存下来。
- `basis` 三档决定措辞，互不混用：`PUBLIC_STATISTIC` 才可写"公开统计显示……（出处）"；`DERIVED` 写"由公开数据推得（公式）"；`PRESS_HYPOTHESIS` 只能写"我们假定……"。
- **事实层 / 假设层分开存**（`facts[]` / `assumptions[]`）：同一份快照里既有"公报说 5.2%"，也有"我们假定失业后等 6 个月"，混在一个数组里，界面必然会把两者排成一样重。

### 6.2 解析器（这就是"预留的接口"）

```
src/server/worldlines/params/
  index.ts      resolveParams(req) → { facts, assumptions, provenance[], status: 'OK' | 'DEGRADED' }
  builtin.ts    内置压力假设（全项目唯一硬编码处，冻结、带版本）
  snapshot.ts   读 data/worldline/*.json → zod 校验 → sha256 → 转 Parameters
  sources.ts    读 data/worldline/sources/*.txt（冻结正文）供逐字校验，不联网
```

**新增一个真实数据来源 = 实现一个 `resolve()` 并注册**：内核、agent 工具、接口、界面一行都不用改。将来接统计年鉴、内部财务模型、用户自定义假设，都走这条路。

### 6.3 demo 怎么"爬"：离线脚本，产物进仓库

```sh
npm run worldline:fetch        # node scripts/worldline-fetch.mjs
# → data/worldline/params.v1.json        参数 + 出处 + 逐字引用
# → data/worldline/params.v1.meta.json   sha256、抓取时间、查询词、命中/未命中字段
```

抓取与校验纪律**参照** `src/server/research.ts` 的 `validateDrafts`，但不能直接复用：那个函数只认贷款条目的 rate/fee 正则，不认统计公报、法条、LPR 表格与派生公式。世界线需要自己实现一个**按 `kind` 分派的校验器**（`exact-quote` / `table-cell` / `formula`），复用的只是"正文包含引用、数字与取值一致、缺依据即回落"这三条原则：

- 每个数值必须配**逐字引用**，跑 `document.content.includes(quote)` 校验，且引用里的数字与取值一致。`document.content` 不在快照里：抓取阶段把正文一起落到 `data/worldline/sources/<documentId>.txt` 并记 sha256，校验只读这些冻结正文（离线可用、可复跑）；
- 单位与口径必须匹配（"失业率"不能拿"登记失业人数"顶上）；
- 拿不到明确依据 → 该字段**回落 BUILTIN 并标 `UNVERIFIED`**，不猜、不补零；
- 只抓公开口径：**10 类**（就业、生活成本、医疗、权益回撤、住房利率、养老、家庭生命周期、失业保障、宏观锚、收入分布；优先级 A–F 六类必需，G/J 可选，清单见附录文档 §1）；**不抓个人隐私**；
- 表格类来源（LPR、分年龄组失业率）没有连续正文，引用取单元格/短句原文（`table-cell` 校验：行 + 列 + 值三要素同时命中），`label` 里写清期限与口径（"5 年期以上"）；
- 网页内容是**不可信数据**，不执行其中指令（沿用研究模块既有约定）。

**运行时零网络**：页面与工具只读快照文件。这一条同时买到三样东西——可复现（快照 + 种子 = 唯一结果）、隔离（§7）、演示不依赖网络。

### 6.4 与现有搜索能力的关系

- `DOUBAO_SEARCH_API_KEY` 已配 → 脚本用它多轮抓取；
- 未配 → 脚本降级为直接 fetch 公开页面，或由 `builtin.ts` 直接生成快照（保证 clone 下来就能演示）；
- P5 若做"刷新参数"按钮，只做**离线快照重建**：后台跑 `worldline:fetch` 生成新版本并提示"下次推演使用 vN"，不回写库、不改当前运行中的参数；不做运行时联网刷新（与 §6.1 去掉 `WEB` 一致）。

### 6.5 agent 侧

- 工具的 `provenance[]` 直接来自参数包；
- 目标管家 prompt 加一条：引用参数时按 `basis` 分三档措辞——`PUBLIC_STATISTIC` 且给了 url 才允许"现实中是……"；`DERIVED` 必须带公式；`PRESS_HYPOTHESIS` 只能"我们假定……"。

## 7. 模块隔离：崩了不许外溢

### 7.1 六层隔离

| 层 | 手段 | 兜底 |
| --- | --- | --- |
| 接口 | 独立前缀 `/api/worldlines/*`，handler 最外层 catch-all | 永远返回 `{status:'UNAVAILABLE', message, retryable}`，不抛未捕获、不 500 白屏 |
| 组件 | `next/dynamic(…,{ssr:false})` + `<WorldlineBoundary>`（error boundary）+ 切到 tab 才加载 | 渲染抛错只卸载子树，页面其余部分照常；显示"本模块暂不可用"+ 重试 |
| 计算 | 内核预算闸门（步数 / 时间 / 规模上限）+ `AbortSignal` 8s | 超限抛 `BUDGET_EXCEEDED`，返回已完成部分 + 明确说明 |
| 数据 | 运行时零网络，只读快照；文件缺失或校验失败 | 回落 `builtin.ts`，状态标 `DEGRADED`，页面说明 |
| 存储 | 只有"保存报告"写新表 | 写失败只影响保存按钮，展示结果仍在内存里 |
| 样式 | `@scope (.worldline-app)` | 不污染 85KB 的 globals |

### 7.2 依赖白名单（这条最要紧）

- **允许**：`domain/worldline/*`（纯函数、无 I/O）、`domain/v2/engine.ts` 的纯函数、`domain/money.ts`、Prisma（只读写新表）；另允许 `server/worldlines/adapter-v2.ts` 作为唯一的服务端 store 接缝。
- **禁止**：`domain/worldline/*` 直接依赖 `server/v2/store.ts`；任何 worker 句柄、`fs` 写入（除保存报告那条路）、`Math.random`。

理由：游戏库的句柄、锁、迁移异常是这个项目历史上最常见的故障源（见 README 的报错复盘）。世界线不该共享这个失败面，只共享纯函数。

### 7.3 事件循环阻塞（最真实的一条风险）

批量内核是同步 CPU 活。30 年 × **2 策略** × 600 条 ≈ **43.2 万次结算**（实际耗时待基准测试），会占住 Node 单线程、拖慢同一进程里的其它页面请求。两步走：

- P1/P2：预算闸门 + 进程内缓存，把默认参数下单次压在 **< 800ms**；
- 若实测超标：把 `kernel.ts` 原样搬进 `worker_threads`（接口不变），主进程只做编排。项目已有独立 worker 进程的先例（撮合 / 策略 worker）。

### 7.4 agent 侧天然隔离

工具抛错会被 `five-agent-runtime.ts` 捕获转成 `{status:'NEEDS_INFORMATION', error}` 回给模型（既有机制）。世界线不可用只让 agent 少一组论据，**不会中断会话**。

### 7.5 回归断言（必须有）

- e2e：故意让 `/api/worldlines/runs` 返回 500 → 首页、目标管家、方案比较、推演 tab 全部照常可用，只有世界线 tab 显示降级卡。
- 单测：`resolveParams` 在快照损坏 / 缺字段时返回 `DEGRADED` 且不抛；内核超预算时抛 `BUDGET_EXCEEDED` 而不是卡死。

| --- | --- | --- | --- |
| 1 这次推演什么 | 目标 + 两/三个付款或投入方案；来源资产与排除原因（折叠）；**参数出处**（"失业率来自公开统计" / "这是压力假设"） | 选方案、改假设（只作为本局假设） | `GET opening` / `GET params` |
| 2 世界线怎么跑 | 条数 / 卡片数 / 种子 / 失业后怎么办 | "让 AI 帮我填这一屏"（agent 建议参数并说明理由）、"再来一把"换种子 | `POST runs` |
| 3 先看整体 | 三层占比（不足/紧巴/乐观）+ P5/P50/P90 表 + 一句 `claim` | 切换 focus（目标达成 / 资金链） | run 结果 |
| 4 抽几张看看 | 扑克牌 2.5:3.5 比例、点击翻转；**盲选**：背面统一中性色，发牌按种子洗乱 | 翻牌、盲选模式、"猜哪张最悲观" | candidates |
| 5 逐月看 | 双栏折线（每策略一栏）+ **共用同一 Y 轴（按绝对余额画）** + 右侧边际分布栏 + 同步游标 | 拖游标看当月；点某月展开两策略当月账本 | `series` + `minUsables` |
| 6 结论卡 | agent 选中的那条 + 说服点 + 出处行 + "这句话我认吗？" | 保存报告 / 复制到规划 / 回上一屏换参数 | agent 结果 |

> 第 5 屏的"共用同一 Y 轴"指**绝对余额**同一个纵轴；两条策略的 `floorMinor` 不同，所以**门槛线各画各的**、色带高度也不同。不许为了让色带看起来一样而改判定口径（§3.5）。

**第 4–6 屏是"把玩"的核心**：盲选先让用户押"哪条最坏"，翻牌后再看统计位置——玩法成本几乎为零，但把"我以为是运气"变成"这是被检验的假设"。

### 8.3 图表实现

- **手写 SVG**，从示范 `renderPanel` / `renderDistribution` 移植（无依赖、与示范视觉一致），封装 `<FanChart>`：输入 `quantileBands`、`pickedLines`、`minUsables`、`floorMinor`、`cursor`。
- 不做：细线群全量渲染（示范的密度雾）。替代方案 = P5–P90 带 + 右侧直方图 + 每条的 rug 刻度；`n ≤ 150` 时可选开"细线雾"。
- recharts 只用于"某条线的逐月柱/折线详情"这类简单图，不硬塞边际分布。

### 8.4 展示口径（硬要求，照规格 §11 + PRD 边界）

| 禁止 | 必须 |
| --- | --- |
| "23% 概率" | "在 200 条模拟里有 20 条……" |
| 最坏值 / min / max | P5 / P50 / P90 |
| "预测" / "将会发生" | "如果……则……" |
| 把事件权重说成真实概率 | 横幅 + `provenance` 标签 |
| "研究表明……"（其实是压力假设） | 按 `basis` 分措辞：`PUBLIC_STATISTIC` 才可引出处，否则写"我们假定……" |
| 建议式结论 | "这条线的代价是……，你认不认这个前提" |

落实手段：出参里就不允许出现"概率/最坏/预测"这些词（单测断言）；`basis === 'PRESS_HYPOTHESIS'` 的参数禁止带"研究/数据显示"字样；页面顶部保留与 v2 一致的"情景假设"提示条。

> 字段名（`minBalanceMinor`、`minUsables`）是**内部标识**，不是展示文案：接口与代码可以继续用，但序列化给 agent 与界面的自然语言里不许出现"最坏值 / 最低点"这类表述，统一说"最紧的时候""第几个月开始不够"。这条同时约束 UI 文案与 agent prompt。

## 9. 接入项目现有"世界线玩法"（平行人生）：低侵入

> 先把"零侵入"说准：**对既有行为零侵入**——不改 `/api/simulations/*`、`/api/v2/*` 的行为，不改游戏页数值，不改 `Run/Setup/Rules/Draws` 结构。但**代码面不是零改动**：场景③需要一个正式的 `v2Store.createRunFromTape` 接缝 + 一个服务端适配器，`PlanningHub` 也要加 tab 分支。文档里凡是写"完全不用改"的地方，只指计算内核与既有接口行为。

### 9.1 现有玩法长什么样（读代码得到的结构）

项目里已经有一个"世界线玩法"，就是「未来可能性推演 · 平行人生」（`/planning` 第 3 个 tab → `IntegratedSimulation` → `LifeSimulator`）：

| 要素 | 现状 | 出处 |
| --- | --- | --- |
| 一个决定 | 买车 60 个月 / 买房 360 个月 | `rulesFor(target).months` |
| 两条策略 | 方案 A/B（全款 / 低首付 / 高首付 三选二） | `Setup.plans`，`ids = ['a','b']` |
| 一条世界线 | `Run.tape: Draws[]`，**一次生成全期**，A/B 共用 | `makeRun()` / `v2Store.create()` |
| 交互 | 逐月推进，遇事件停下等用户选（降薪/等待/临时工；接受/拒绝职业机会） | `advance()` / `choose()` |
| 局部前瞻 | 每个选项给"已知本月事件、之后无新事件"的六个月试算 | `trials()` + `quietDraws()` |
| 结局 | 共同成功月份、差额、各自剩余资金/负债/累计支付 | `toPublic().summary` |
| 重玩 | **同一份 tape**、可改方案或一次历史选择，其余按月份/路径/事件沿用 | `replay` + `inherited` |
| 对外 | 公开接口**不返回 tape**（有意为之） | `PublicRun` 无 tape 字段 |

一句话：**现有玩法 = "一条世界线 × 两个策略"的交互版；新模块 = "N 条世界线 × 两个策略"的批量版。** 两者共享 `Draws` 语义与结算函数；`SimulationOpening → v2 Setup` 统一经过 adapter，不能把两种 opening 类型直接当成同一对象。

### 9.2 只读就能用的三个接缝

| 接缝 | 现状 | 世界线怎么用 | 是否要改现有代码 |
| --- | --- | --- | --- |
| `reveal / settle / stateOf / initialState` | `engine.ts` 已导出，纯函数 | 批量驱动的全部计算 | **不用**（见 §3.1） |
| `createRunFromTape(session, setup, tape)` | 现有 `makeRun()`/`v2Store.create()` 位于 `server/v2/store.ts`，公开接口不返回 tape | 世界线只通过薄服务端适配器调用正式的 `createRunFromTape` 接缝，服务端完成 session/workspace 归属 | **允许新增受限 store 接口；不改现有 API 行为** |
| `GET /api/simulations/opening` → `calculate()` | 冻结的是财务模拟的 `SimulationOpening`；v2 路由再通过 `calculate()` 映射成 v2 `Setup` | 世界线调用同一 adapter，不自己拼 `Setup` | **新增 adapter；不改既有接口行为** |

三处接缝合起来说明：计算内核与现有页面保持新增文件隔离；场景③需要一个**服务端受限适配器**接入 v2 store，不能再宣称所有接入点都只靠新增文件完成。

### 9.3 顺带定下一个拍板点：策略数锁 A/B 两条

因为 `settle(state, pending, selections, setup)` 一次结算 A/B 两条 path，批量内核不需要单路径版本；一旦要 3 条策略，就必须从 `settlePath` 抽出单路径函数（**那才需要动 `engine.ts`**）。所以：

- 本期：**锁 A/B 两条**，`engine.ts` 零改动；
- 将来若要 3 条（全款 / 低首付 / 高首付同时比）：单独一个 PR 做"抽 `settleSinglePath`"的行为不变重构，并先用 `tests/v2.test.ts` + §10.2 锁死行为，再开批量。

### 9.4 三个接入场景（游戏页本身不改）

| 场景 | 用户看到的位置 | 只读用到 | 产物 | 现有代码改动 |
| --- | --- | --- | --- | --- |
| ① 开局前："这事值不值得" | PlanningHub 新 tab「世界线对比」，与「未来可能性推演」并列 | `GET simulations/opening` | 六屏把玩 + 候选 + 报告 | 新增 tab、渲染分支、状态与 initialTab 接线 |
| ② 结局后："我走的这条线排在哪" | 世界线 tab 里的"锚定一局最近的人生"选择器（读推演记录列表） | `GET simulations/reports` + `PublicRun.timeline` | 分布图上标一条**"你走过的线"**；标注为**样本外**，不参与分档统计 | 新增读取与展示分支 |
| ③ 假设线 → 能体验的一局 | 屏 6 的"用这段经历进游戏"按钮 | 服务端取的该世界线 `Draws[]` | 新 run → `LifeSimulator`（已有 `initialRunId` 入口） | 新增受限 server adapter + v2 store 正式接缝 |

三个场景的分工很干净：**① 给规划当参考数据，② 给结局做定位，③ 把统计结果变成可体验的故事。** ②③ 都只是"读"和"造新局"，从不修改既有局。

> ② 的诚实点：用户走过的那一局，事件序列是 `tapeFor()` 随机生成的、不是从世界线种子来的，所以它在分布里**只能当参考点**，不能参与"这 400 条里有多少条不足"的计数。页面上要写明"这一条是你真走过的那条，不在 N 条样本内"。

### 9.5 只读契约（红线，写进 PR 自查）

1. **不从客户端或世界线纯内核直接 import `v2Store`**。造 run 只走 `server/worldlines/adapter-v2.ts`；该适配器是唯一允许调用 `v2Store.createRunFromTape(session, setup, tape)` 的服务端接缝，并负责 workspace/session 归属、权限与错误转换。
2. **不 `mutate` 任何既有 run**；场景 ③ 只 `create` 新 run（和用户点"新故事"没有区别）。
3. 不改 `Run / Setup / Rules / Draws` 的结构，不改 `ids`，不改 `rulesFor()` 的默认概率。
4. 不改 `/api/simulations/*` 与 `/api/v2/*` 的行为；世界线只新增 `/api/worldlines/*`。
5. 不公开 tape：场景 ③ 必须**服务端**完成（`PublicRun` 不含 tape 是有意的设计）；新 store 接缝必须加入 workspace 清除与删除测试。
6. 不动 `globals.css` / `game.css`；新增 `worldline.css` 且 `@scope (.worldline-app)`。
7. 既有 docs（PRD、规则、验收记录）不改，只新增本文。
8. `PlanningHub` 不只是加联合类型：还要新增 tab、渲染分支、状态、`initialTab` 和加载/错误边界；若不想改现有组件，则退化为独立路由 `/worldlines`。

### 9.6 文案分工（别让用户以为是同一个东西）

| | 未来可能性推演（平行人生） | 世界线对比（本模块） |
| --- | --- | --- |
| 用户角色 | 当事人，做决定 | 观察者，看分布 |
| 应对策略 | 自己选 | **全局固定**（否则不可比） |
| 时间 | 逐月，可停 | 一次跑完 |
| 输出 | 一段人生 + 结局 | 三档占比 + P5/P50/P90 + 几条代表线 |
| 共同 | 同一底账、同一规则、同一结算函数 | 同左 |

要写清的一句话：**"想体验一次，进平行人生；想知道有多少种可能，用世界线对比。"**
以及场景 ③ 的提醒：**"这一局的经历和那条世界线一致，但选择由你来做，所以它会偏——这正是'同经历重玩'的既有规则。"**

### 9.7 参数与现有概率的关系

`rulesFor()` 里的 `probabilities`（每百万：医疗 1000、失业 2000、奖金延期 200000、市场下跌 5000、职业机会 5000）是**游戏里的故事权重**，规则文档已明确"权重不代表现实概率"。世界线参数包做的是**压力化覆盖**：

- 默认（离线 `builtin`）：把失业、医疗、市场下跌整体上调到"值得一看"的量级，并全部标 `PRESS_HYPOTHESIS`；
- 接真实数据（`snapshot`）：失业率、医疗自付、权益回撤来自公开统计时标 `PUBLIC_STATISTIC` 并附出处；
- 覆盖只发生在世界线自己的参数对象里，**不改 `rulesFor` 的默认值**，所以游戏页数值一字不变。

### 9.8 与五管家

- 世界线是**规划阶段的参考数据**：目标管家回答"这个目标到底有多稳"时引用它。
- 结论卡可以进 `FuturePlanningReport` 的 `claim`（"另外 180 条已扫描，未发现新的失败模式"这类句子本来就是行动清单的论据）。
- 不新增 PROPOSE 类工具：世界线不产生"待确认事项"，只产生论据。

## 10. 验收与测试

### 10.1 内核单测（`src/domain/worldline/*.test.ts`）

1. **确定性**：同 `(seed,n,k,params)` 两次调用，`candidates`、`bands`、`quantiles` 逐字段相等。
2. **配对**：同一 `i` 的 `tape` 在各策略间完全相同；两条策略的差异不随种子漂移（对比两组种子）。
3. **增量稳定**：`n=100` 的前 100 条 == `n=400` 的前 100 条。
4. **统一基准（逐张断言）**：每张卡的 `band` 与所在分区一致——乐观卡两个策略都 `ok`；紧巴卡至少一个 `tight` 且无 `bad`；不足卡至少一个 `bad`。（示范 §7.4 的回归断言）
5. **口径自洽**：「中途失败条数」与「到期不足条数」分列，且后者 ≤ 前者。
6. **账目**：任一世界线任一月 `期末 = 期初 + 收入 − 支出 − 月供`（v2 已有 `assertBalance`，这里断言它没被绕过）。
7. **文案禁令**：序列化后的出参不含 `概率/最坏/预测/将会`。
8. **性能**：按 2 策略测，`n=400 × 5 年` 目标 < 300ms、`n=200 × 30 年` 目标 < 800ms（`vitest` 里用 `performance.now()` 打点）；实现完成后以真实基准更新这两个数，不拿拍脑袋指标当验收失败理由。未来开第三条策略时指标同比调整并重测。
9. **参数出处完整**：每条 `Param` 必有 `source`、`basis`、`label`；`PUBLIC_STATISTIC` 必须带 `url + retrievedAt + quote`，且 `quote` 能在冻结正文（`data/worldline/sources/<documentId>.txt`）里逐字命中；`PRESS_HYPOTHESIS` 不得带 url，也不得出现"研究/数据显示"字样。
10. **快照健壮性**：快照缺字段 / 数值越界 / sha256 不匹配 → `resolveParams` 返回 `DEGRADED` 并回落 `builtin.ts`，不抛异常。
11. **推导可复算**：`DERIVED` 的 `inputs` 必须全部存在于同一参数包，按 `formula` 复算能落到 `value`（同一舍入）；缺 `derivation` 即判失败。
12. **分层不许混**：`assumptions[]` 里出现 `PUBLIC_STATISTIC`、或 `facts[]` 里出现 `PRESS_HYPOTHESIS` 都判失败（防止"把假设写成统计"）。
13. **来源等级**：`basis === 'PUBLIC_STATISTIC'` 时 `sourceQuality` 必填；`OFFICIAL` 的 url 域名必须在白名单（stats.gov.cn、nhc.gov.cn、gov.cn、mohrss.gov.cn、pbc.gov.cn、spp.gov.cn 等）；`THINK_TANK` / `THIRD_PARTY` 的 `label` 必须含机构名，不得写成"国家统计局数据"。

### 10.2 引擎一致性（最关键的一条）

把某个世界线以 **v2 交互模式**跑一遍（同一 `setup`、同一份 `tape`、同一条选择序列，走 `advance`/`choose`），月末账本与批量内核结果**逐字段相等**。因为两边调的是同一个 `settle`，这条测试的作用是锁住"批量驱动没有绕开规则"（尤其是 `selections` 的策略、`medicalUntil`、`bonusDue` 的时序）。这条通过，就说明"两个页面说同一个数"。

### 10.3 服务与界面

- API：未授权工作区 403；`portfolioRevision` 变化返回 `STALE`；同 `requestKey` 幂等。
- 清除：新增测试——删除工作区业务资料后 `worldlineReport` 为空；`dataOverview` 不再返回世界线报告；`deletionPreview` 的 affected 列表含"世界线报告"。
- e2e（Playwright，独立 3100 端口）：六屏走通 → 翻卡 → 保存报告 → 列表可见。
- 常规闸门：`npm run typecheck`、`npm run lint`、`npm test`（分组 180s 超时不放宽）。

### 10.4 数字对拍

示范 §14 那张表（`seed=42, n=400`）**不能**直接对拍——它的汇率/参数是占位（元）、规则集也不同。做法：
- 保留示范参数为**冻结 fixture**（`tests/fixtures/worldline-reference.ts`），只用来断言**结构**（分档占比之和 = n、卡片档位与色带一致等）；
- 数值对拍改为本项目口径下的**新金标**：同一 opening + seed 下把关键数字（`bands`、`quantiles`、候选 id）写进快照测试，改规则必须显式更新快照并说明。

## 11. 性能与上限

| 项 | 值 | 依据 |
| --- | --- | --- |
| `n` 默认 | 5 年 400 / 30 年 200 | 结算次数 ≈ `n × 策略数 × 月数` |
| `n` 上限（UI/工具） | 600 | 30 年 × 2 策略 × 600 = 43.2 万次结算；耗时以基准测试为准，超预算时降 `n` 或挪 worker |
| `months` 上限 | 360 | 目标跨度上限 |
| 单次工具出参 | ≤ 6KB（候选 ≤ 8） | 24 次工具 / 上下文预算 |
| 进程内缓存 | 32 条 LRU | 参数微调时命中 |
| UI 首屏数据 | 30–60KB | 分位带 + `minUsables` + ≤6 条全序列 |

若实测超预算，退路（按代价排序）：抽稀 `tape` 的月数（不支持）→ 降 `n` → 服务端预聚合（已是）→ 只算 P5/P50/P90 而跳过候选筛选（不支持，会破坏 ③ 闸门）。

### 16.2 卡片口径调整（同日，按用户要求）

- **最多 6 张**：`MAX_CARDS = 6`，`k` 入参从 1..4 放宽到 1..6，默认 6；工具出参候选也从 8 收到 6。
- **分档改成排名五档**：不再是"乐观/偏乐观/紧巴/不足"，而是按统一标量 `worstUsable` 排名切成
  **优 / 次优 / 中 / 次劣 / 劣**（各 20%）。标签直接取档名，`candidate.tier` 一并下发给页面与 agent。
- **挑卡从差的一头留下**：`劣 → 次劣 → 次优 → 中 → 优`。所以
  k=3 正好是「劣 / 次劣 / 次优」，k=4 不含「优」，k=6 才把样本最多的那一档对半拆开（同一档两条不同故事）。
- 一档一张：不会再因为"多给候选"而多出卡片；去重仍按事件组合签名。

测试相应改为：k=3 只含 `worst/secondWorst/secondBest`、k=4 不含 `best`、k=2 只剩 `worst/secondWorst`、
任何 k 都不超过 6 张且不重复。
差的、留给下一轮：

1. `WorldlineReport` 表与清除链路（现在不落库，刷新即重算）；
2. `worldline:fetch` 快照脚本 + 冻结正文（现在卡片出处取自调研稿逐字摘录）；
3. 卡组由用户在页面确认（目前页面固定用默认卡组，agent 走 `proposeEventCardPlan`）；
4. `getWorldlineDetail` 之外的"按月悬停看账目"还没做（图上有游标，没有逐月明细表）。

### 16.1 修掉的第一个线上问题（同日）

用户第一次打开页面就撞到"参数无效，请核对车价、首付比例及期限"。两个原因：

1. `runInputSchema` 用了 `.strict()` 且只接受 number，而页面会把金额显示成"元"、把数字给成字符串，键盘输入还可能带逗号；
2. `src/server/http.ts` 的 ZodError 兜底文案是车贷专用的，等于把真正出错的字段名吞掉了。

修法：

- 入参挪到 `src/server/worldlines/input.ts`，改成**宽容解析**（`"400"` / `400`、缺 `cardPlan`、多一个字段都能过），语义校验仍在服务层；
- 页面金额统一走 `toMinor()`（去逗号、按分取整）再提交；
- 路由自己接住 ZodError，返回"参数没读懂：月收入：…"这种能照着改的句子；
- `input.test.ts` 6 条：脏输入能过、真错误照样拦、字段名可读；
- 页面从"四步"压成**两屏一步**：`确认输入（可折叠修改）→ 勾选 → 开始推演 → 结果（占比 + 卡片 + 逐月同屏）`。

实测：`n=400 × 60 月` 0.95–1.3s；页面与接口日志全 200；`tsc` 干净；81 条相关单测全绿。
